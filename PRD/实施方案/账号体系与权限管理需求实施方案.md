## 一、实施结论

本期包含 2 个一级需求：

1. 登录与注册。
2. 访问权限与账号管理。

结合需求依赖、数据安全风险和现有系统结构，将两个一级需求拆分为以下 4 个实施阶段：

| 顺序 | 实施阶段 | 优先级 | 核心结果 |
| --- | --- | --- | --- |
| 1 | 账号与认证基础 | P0 | 建立可信账号身份，支持注册、登录、退出和当前账号查询 |
| 2 | 页面权限与聊天数据隔离 | P0 | 后端阻止越权访问，会话、消息和图片严格归属于当前账号 |
| 3 | 登录注册及账号状态前端 | P1 | 按原型完成弹窗、页头、路由跳转和账号会话界面 |
| 4 | Console 账号管理 | P1 | admin 可查询账号、调整角色以及启用或停用账号 |

实施依赖关系为：账号与认证基础 → 页面权限与聊天数据隔离 → 登录注册前端 → Console 账号管理。后续阶段不得绕过前置阶段单独上线。

- 账号注册、登录、退出和当前账号查询。
- 普通用户与 admin 两种角色。
- 正常、已停用两种账号状态。

- 账号删除和数据注销。
- 会话手工重命名、删除和消息正文全文搜索。
- Manus 任务在服务重启后的自动续跑或自动重试。
- 对象存储及多存储后端切换。
- 管理员代替用户创建账号。
- 管理员查看、搜索或导出其他账号的聊天内容。
- 聊天记录共享、转移或公开。
- 头像、昵称和其他个人资料维护。

## 四、现状与改造重点

| 领域 | 当前状态 | 与需求的差距 | 改造重点 |
| --- | --- | --- | --- |
| 身份 | 系统没有统一账号身份 | 无法识别当前操作者 | 建立账号、认证会话和当前用户上下文 |
| 页面权限 | Landing、Chat、Console 均可直接访问 | 访客和普通用户可以越权进入受限页面 | 前端路由控制与后端接口鉴权同时落地 |
| Chat 会话 | 前端生成并直接提交 `chatId` | 任意用户可构造其他 `chatId` | 服务端创建会话并校验会话所有权 |
| 会话列表 | 保存在浏览器 `localStorage` | 无法跨设备同步，切换账号可能串数据 | 会话列表改为服务端数据库数据 |
| 页面消息 | 主要保存在 Chat 页面内存 | 刷新后无法恢复完整页面消息 | 提供会话消息查询接口并持久化展示数据 |
| AI 记忆 | 已支持 file、MySQL、Redis 多种实现 | 仅按 `conversationId` 存取，没有账号归属 | 使用持久化存储并在存取前验证账号归属 |
| 图片上传 | 文件名包含前端传入的 `chatId` | 无法证明图片属于当前账号 | 上传前验证会话，保存账号和会话关联信息 |
| Console | 只有系统状态、会话管理和调试功能 | 没有账号查询与管理能力 | 在原有功能前新增账号管理区域 |

## 五、总体实现原则

### 5.1 身份可信

- 后端从认证会话解析当前账号，禁止相信前端提交的账号、角色和用户 ID。
- 所有需要登录的接口统一从服务端用户上下文获取当前用户。
- 普通用户和 admin 使用相同登录入口，角色仅由服务端账号数据决定。

### 5.2 前后端双重权限控制

- 前端控制导航入口、路由跳转和页面展示，提供正确的用户体验。
- 后端对每一个受限接口执行身份和权限校验，前端隐藏入口不能替代后端鉴权。
- 未登录统一返回未认证错误；已登录但角色不足统一返回无权限错误。

### 5.3 持久化与账号隔离

- 账号、会话元数据、消息和附件关联信息使用持久化数据库保存。
- 前端 `localStorage` 不再作为会话列表和消息归属的事实来源。
- 每次读取、发送、续聊和上传图片前，都必须验证会话属于当前账号。
- admin 的管理权限不包含查看其他账号聊天内容。

### 5.4 会话认证方式

- 使用服务端认证会话和安全 Cookie 保存登录状态。
- Cookie 需要设置 `HttpOnly`，生产环境设置 `Secure`，并配置合适的 `SameSite` 策略。
- Cookie 关闭浏览器后仍保留；认证会话连续 24 小时没有有效访问后失效，并设置 7 天绝对有效期。
- 同一账号允许多设备并发登录，各设备认证会话相互独立；退出登录只注销当前设备会话。
- 前端首次发起登录或注册前先请求 `/auth/csrf`，并在修改类请求的 `X-CSRF-TOKEN` 请求头中携带 Token；Token 只保存在当前页面内存中。
- 登录或注册成功会轮换 Session ID，并使登录前 Token 失效；认证 Store 必须立即重新请求 `/auth/csrf`，新 Token 获取成功前禁止发起退出或其他修改类请求。
- 修改请求收到 CSRF `403` 时，前端重新获取 Token 并调用 `/auth/me` 校验登录态，不自动重复提交原修改请求，避免重复写入业务数据。
- Axios、Fetch SSE 和 EventSource 请求需要统一携带认证 Cookie。
- 不在 URL、日志或浏览器本地存储中保存密码、会话密钥或长期有效认证令牌。
- 修改角色后，服务端权限判断立即读取最新角色，使 Console 权限立即生效或失效。
- 停用账号不主动中断已有认证会话；账号下一次登录时再阻止登录，符合 PRD 已确认规则。
- 已建立的 SSE 或 Manus 流式请求不因执行期间认证会话到期而被主动中断；请求结束后的下一次请求重新鉴权。

### 5.5 数据库选择

- 账号、会话和消息使用现有 MySQL 持久化链路，复用 MyBatis Plus 和 `MySqlChatMemory` 基础能力。
- 正式环境需要固定启用 MySQL 会话存储，file 和 Redis 实现不作为跨设备历史记录的最终数据源。
- PgVector 继续负责 RAG 向量数据，不承载账号和业务会话主数据。

## 六、核心数据设计

### 6.1 账号表 `ai_user_account`

| 字段 | 说明 | 约束 |
| --- | --- | --- |
| `id` | 账号主键 | 全局唯一 |
| `account` | 账号展示值 | 去除首尾空格后保留原始大小写，必填 |
| `normalized_account` | 账号规范值 | 将 `account` 中英文字母转为小写，必填、唯一 |
| `password_hash` | 加密后的密码摘要 | 必填，禁止保存原始密码 |
| `role` | 账号角色 | `USER` 或 `ADMIN` |
| `status` | 账号状态 | `ACTIVE` 或 `DISABLED` |
| `register_time` | 注册时间 | 注册成功时写入 |
| `last_login_time` | 最后成功登录时间 | 从未登录时为空 |
| `create_time` | 创建时间 | 系统维护 |
| `update_time` | 更新时间 | 系统维护 |

关键约束：

- `normalized_account` 建立唯一索引，确保英文字母大小写不同的同一账号不能重复注册。
- `account` 与 `normalized_account` 均按去除首尾空格后的值生成，账号展示只使用 `account`，登录查询只使用 `normalized_account`。
- 账号长度为 3～32 个字符，只允许中文、英文字母、数字、下划线、短横线和英文句点，且首尾必须为中文、英文字母或数字。
- `password_hash` 使用 Spring Security `PasswordEncoder` 生成，不单独保存可还原密码的字段。
- 公开注册只能写入 `USER` 和 `ACTIVE`，前端不得提交角色和状态。
- 账号不提供物理删除操作。

### 6.2 会话表 `ai_chat_session`

| 字段 | 说明 | 约束 |
| --- | --- | --- |
| `id` | 会话主键 | 全局唯一 |
| `session_id` | 对外会话标识 | 服务端生成、唯一 |
| `user_id` | 所属账号主键 | 必填，关联账号表 |
| `app_code` | 会话所属应用 | Love App、Manus 等 |
| `title` | 会话标题 | 用于左侧会话列表 |
| `create_time` | 创建时间 | 系统维护 |
| `update_time` | 最后活跃时间 | 新消息写入时更新 |

关键约束：

- 会话只能由当前登录账号创建。
- 会话列表始终按 `user_id` 查询，不允许管理员查询其他账号会话。
- `session_id` 由服务端生成，禁止使用客户端随机值直接建立归属。
- 会话查询使用 `session_id + user_id` 联合条件，避免只按会话 ID 查询。
- 前端新建操作只产生空白草稿，首次发送有效消息时才创建服务端会话。
- `title` 由首条有效用户消息生成：文本清理空白后总长度不超过 30 个字符，超出时保留前 29 个字符并以“…”作为第 30 个字符；纯图片消息固定为“图片会话”；生成后不自动更新。

### 6.3 消息表 `ai_chat_memory_message`

在保留现有消息载荷能力的基础上，与 `ai_chat_session` 建立明确关联：

| 字段 | 说明 | 改造要求 |
| --- | --- | --- |
| `id` | 消息主键 | 保留 |
| `conversation_id` | 会话标识 | 对应服务端生成的 `session_id` |
| `payload_json` | Spring AI 消息载荷 | 保留，禁止包含明文密码 |
| `create_time` | 创建时间 | 保留 |
| `update_time` | 更新时间 | 保留 |

消息存取前先通过会话表验证当前账号拥有该 `conversation_id`。页面需要的用户消息、AI 消息、Todo 和提问信息，应使用可稳定恢复的消息结构持久化，不能只存在前端内存或 Manus 进程内存中。

### 6.4 附件表 `ai_chat_attachment`

| 字段 | 说明 | 约束 |
| --- | --- | --- |
| `id` | 附件主键 | 全局唯一 |
| `session_id` | 所属会话标识 | 必填 |
| `user_id` | 所属账号主键 | 必填 |
| `original_name` | 原始文件名 | 仅用于展示 |
| `storage_name` | 实际文件名 | 服务端生成 UUID，不使用原始文件名 |
| `storage_path` | 服务端存储位置 | 禁止由客户端直接指定 |
| `content_type` | 文件类型 | 仅允许受支持的图片类型 |
| `file_size` | 文件字节数 | 单张不超过 10 MB |
| `create_time` | 上传时间 | 系统维护 |

附件上传、读取和消息引用均按当前账号校验，接口不返回可越权访问的任意本地文件路径。用户上传图片和 AI 生成图片统一登记到该表；实际文件保存到 `ATTACHMENT_STORAGE_ROOT` 指定的持久化目录。仅接受 JPEG、PNG、WebP，并同时校验扩展名、声明 MIME 类型和文件真实内容。附件随会话长期保留，本期不自动过期。

### 6.5 Manus 执行表 `ai_agent_execution`

| 字段 | 说明 | 约束 |
| --- | --- | --- |
| `id` | 执行主键 | 全局唯一 |
| `execution_id` | 对外执行标识 | 每次执行由服务端生成、唯一 |
| `session_id` | 所属会话标识 | 必填，关联当前账号会话 |
| `user_id` | 所属账号主键 | 必填 |
| `status` | 执行状态 | `RUNNING`、`WAITING_USER`、`COMPLETED`、`FAILED`、`INTERRUPTED` |
| `task_payload` | 执行任务 | 可恢复展示，不用于重启后自动续跑 |
| `todo_payload` | Todo 状态 | 可恢复展示 |
| `question_payload` | 补充问题 | 中断后只读展示 |
| `reason` | 失败或中断原因 | 成功执行时可为空 |
| `create_time` | 创建时间 | 系统维护 |
| `update_time` | 更新时间 | 状态变化时更新 |

服务启动时，将遗留的 `RUNNING`、`WAITING_USER` 记录统一更新为 `INTERRUPTED`，原因记录为服务重启。该处理不自动恢复或重跑任务；用户明确重新发起时创建新的 `execution_id`，原会话仍可正常聊天。

## 七、阶段一：账号与认证基础（P0）

### 7.1 账号领域能力

#### AUTH-01 创建账号数据结构

- 建立账号实体、Mapper、Service 和数据库表结构。
- 定义 `USER`、`ADMIN` 角色和 `ACTIVE`、`DISABLED` 状态枚举。
- 账号查询、角色判断和状态判断统一通过账号服务完成。
- 关键账号操作记录日志，但日志不得打印密码、密码摘要和认证 Cookie。

#### AUTH-02 初始化 admin

- 系统正式开放前必须存在至少一个正常状态的 admin。
- admin 初始化只读取环境变量 `BOOTSTRAP_ADMIN_ENABLED`、`BOOTSTRAP_ADMIN_ACCOUNT`、`BOOTSTRAP_ADMIN_PASSWORD`，不从 Nacos、配置文件默认值或代码常量读取真实账号和密码。
- 仅当 `BOOTSTRAP_ADMIN_ENABLED` 启用且账号表为空时创建初始 admin。
- 初始密码至少 12 位，并且同时包含英文字母、数字和特殊字符。
- 初始化过程可重复执行：账号表非空时不创建账号、不提升角色，也不覆盖已有密码。
- 账号表非空但不存在正常状态 admin，或配置账号与已有非 admin 账号冲突时，初始化校验失败并要求人工处理，禁止自动修改既有账号。
- 初始化日志只记录账号标识和执行结果，不记录初始密码。

### 7.2 注册能力

#### AUTH-03 注册参数校验

- 账号必填，先去除首尾空格，再校验长度为 3～32 个字符。
- 账号只允许中文、英文字母、数字、下划线、短横线和英文句点，首尾必须为中文、英文字母或数字。
- 将账号中的英文字母转为小写生成规范值，并按规范值检查是否已存在；页面展示值保留去除首尾空格后的原始大小写。
- 密码必填，长度至少 6 位，并且同时包含英文字母和数字。
- 确认密码必填，并与密码完全一致。
- 前端校验用于即时提示，后端必须重复执行完整规则校验。

#### AUTH-04 注册写入

- 使用安全密码编码器生成 `password_hash`。
- 新账号固定写入普通用户角色和正常状态。
- 使用数据库唯一约束处理并发注册同一账号的情况。
- 注册成功后建立认证会话并返回当前账号信息，实现“注册并登录”。
- 注册成功后前端必须重新获取 CSRF Token，再开放退出及其他修改操作。
- 记录账号注册成功日志，不记录原始密码。

### 7.3 登录能力

#### AUTH-05 登录校验

- 去除登录账号首尾空格，并将英文字母转为小写后按 `normalized_account` 读取账号记录。
- 使用密码编码器校验密码；登录输入的大小写不覆盖账号原有展示值。
- 账号不存在或密码错误统一返回“账号或密码错误”。
- 账号已停用时返回“账号已停用，请联系管理员”。
- 登录失败不得通过状态码、错误码或响应耗时暴露账号是否存在。

#### AUTH-06 登录成功处理

- 建立服务端认证会话。
- 记录认证时间和最后活跃时间，用于校验 24 小时不活跃期限和 7 天绝对有效期。
- 允许同一账号建立多个相互独立的设备会话，不因新登录使其他设备会话失效。
- 更新账号最后登录时间。
- 返回账号 ID、账号名称、角色和状态，不返回密码相关字段。
- 登录成功后前端必须重新获取 CSRF Token，再开放退出及其他修改操作。
- 记录登录成功日志和必要的审计信息。

### 7.4 退出与当前账号

#### AUTH-07 查询当前账号

- 已登录时返回当前账号、角色和状态。
- 角色从账号数据读取最新值，保证角色调整后已有会话的下一次请求立即按新角色鉴权。
- 账号状态不用于强制注销停用前已存在的认证会话；停用状态只阻止建立新的认证会话。
- 未登录时返回明确的未认证响应。
- 前端刷新页面后通过该接口恢复账号状态。

#### AUTH-08 退出登录

- 只使当前设备的服务端认证会话失效并清理认证 Cookie，不影响其他设备会话。
- 退出请求必须携带当前登录会话重新签发后的 CSRF Token，不得复用登录前 Token。
- 不删除账号数据、会话历史和聊天附件。
- 前端退出后清除当前账号的页面状态，再跳转 Landing。

#### AUTH-09 会话有效期与流式请求

- 认证会话连续 24 小时没有有效访问时失效，每次有效访问更新最后活跃时间。
- 认证会话自创建起最长保留 7 天，达到绝对有效期后即使持续活跃也必须重新登录。
- 使用持久化 Cookie 保证浏览器关闭后仍可恢复未过期会话；Cookie 设置 `HttpOnly`，生产环境设置 `Secure`，并按部署方式设置 `SameSite`。
- SSE 或 Manus 请求建立连接时完成认证；连接建立后若会话在执行中到期，不主动中断该次请求，后续新请求重新校验。

### 7.5 认证接口

| 方法 | 接口 | 权限 | 说明 |
| --- | --- | --- | --- |
| `GET` | `/auth/csrf` | 公开 | 创建或读取当前会话的 CSRF Token；登录或注册成功后必须重新调用 |
| `POST` | `/auth/register` | 公开 | 注册普通账号并自动登录 |
| `POST` | `/auth/login` | 公开 | 账号密码登录 |
| `POST` | `/auth/logout` | 已登录 | 退出当前认证会话 |
| `GET` | `/auth/me` | 已登录 | 查询当前账号信息 |

### 7.6 阶段完成标准

- 合法账号可以注册并自动登录。
- 重复账号不能注册。
- 账号首尾空格被去除，英文字母不区分大小写，账号长度与字符范围符合已确认规则。
- 不符合密码规则或两次密码不一致时不能注册。
- 错误账号和错误密码返回相同提示。
- 已停用账号不能建立新的登录会话。
- 密码在数据库、响应和日志中均不以明文出现。
- 刷新页面后可以恢复当前登录账号。
- 浏览器关闭后可恢复未过期会话；24 小时不活跃或创建满 7 天后必须重新登录。
- 多设备会话相互独立，退出只影响当前设备。
- 退出后原认证会话不能继续访问受限接口。
- 登录和注册成功后重新获取 CSRF Token，使用新 Token 可以退出；旧 Token 必须被拒绝。

## 八、阶段二：页面权限与聊天数据隔离（P0）

### 8.1 页面和接口权限

#### ACL-01 定义公开接口

- Landing 静态页面和登录、注册接口允许公开访问。
- 健康检查是否公开按照部署环境控制，不与业务账号权限混用。

#### ACL-02 定义登录接口

- Chat 会话、消息、AI 调用、Manus 续聊和图片上传必须登录。
- 未登录访问统一返回未认证错误，禁止业务控制器自行返回模糊空数据。

#### ACL-03 定义 admin 接口

- Console 账号管理接口仅允许 admin 调用。
- 每次调用读取账号最新角色，确保 admin 被降级后权限立即失效。
- 普通用户即使手工调用接口也必须返回无权限错误。

### 8.2 会话归属与持久化

#### CHAT-01 服务端创建会话

- 用户点击“新建会话”时前端只创建空白草稿，不调用创建接口。
- 首次发送非空文本或有效图片时创建正式会话，由服务端生成 `session_id` 并绑定当前账号。
- 保存应用类型、默认标题、创建时间和最后活跃时间。
- 文本标题将首条用户消息中的连续空格、制表符和换行整理为单个空格；标题总长度不超过 30 个字符，超出时保留前 29 个字符并以“…”作为第 30 个字符。
- 首条消息只有图片时标题为“图片会话”；标题生成后不随后续消息自动变化，本期不提供重命名和删除。
- 前端不再把随机生成的 `chatId` 直接视为有效业务会话。

#### CHAT-02 查询当前账号会话列表

- 只查询当前账号的会话。
- 支持服务端标题搜索：关键词去除首尾空格，英文字母不区分大小写，不查询消息正文。
- 默认每批返回 20 条，使用基于 `update_time + id` 稳定排序的游标分页，并按更新时间倒序返回会话 ID、标题、应用和更新时间。
- 后端限制 `limit` 最小为 1、最大为 100；前端本期不提供单批数量选择。
- 搜索条件变化时清空已有结果并从首个游标重新查询。
- 账号切换后重新请求列表，不复用上一账号缓存。

#### CHAT-03 查询会话消息

- 根据当前账号和会话 ID 联合查询。
- 会话不存在和会话不属于当前账号均不得返回消息内容。
- 返回能够恢复用户消息、AI 消息、图片、Todo 和提问状态的结构。

#### CHAT-04 发送消息和 AI 调用

- 同步、SSE、SseEmitter、Manus 和 Todo 等入口统一执行会话归属校验。
- 后端向 Spring AI 传递经过校验的服务端会话标识。
- AI 回复完成或发生异常时，按统一规则更新会话状态和最后活跃时间。
- SSE 断开不能导致已经落库的用户消息丢失或归属错误。

#### CHAT-05 Manus 状态隔离与中断记录

- `ManusSessionStore` 的会话键使用服务端会话标识，并在进入 Service 前验证所有权。
- 继续执行、提交答案、Todo 监听和移除会话均校验当前账号。
- 每次执行生成独立 `execution_id`，持久化任务、Todo、补充问题、状态、时间和失败或中断原因。
- 服务启动时将遗留的 `RUNNING`、`WAITING_USER` 执行标记为 `INTERRUPTED`，页面显示“服务重启导致执行中断”。
- 重启后不自动恢复或重跑任务；历史消息、Todo 和补充问题继续展示，其中补充问题只读且不能向原执行提交答案。
- 用户可在原会话明确发起新执行，新执行使用新的 `execution_id`，原会话的其他聊天能力继续可用。

### 8.3 图片归属

#### CHAT-06 图片上传

- 上传接口先校验当前账号拥有目标会话。
- 文件写入环境变量 `ATTACHMENT_STORAGE_ROOT` 指定的服务端持久化目录，禁止使用临时目录、构建输出目录和前端静态资源目录。
- 服务端以 UUID 生成实际文件名，客户端原始文件名仅保存为元数据，不能控制实际路径。
- 仅允许 JPEG、PNG、WebP，单张图片不超过 10 MB；同时校验扩展名、声明 MIME 类型和真实文件内容，拒绝 GIF、SVG 及其他格式。
- Spring Multipart 的 `max-file-size` 固定为 `10MB`，`max-request-size` 固定为 `12MB`；总请求上限高于单文件上限，用于容纳 Multipart 协议开销，确保 1～10 MB 的合法图片能够进入业务校验。
- 单文件超过上限时由全局异常处理器捕获 `MaxUploadSizeExceededException`，返回 HTTP `413 Payload Too Large`、业务码 `41301` 和“单张图片不能超过 10 MB”，并打印不包含文件内容和认证信息的告警日志。
- 用户上传图片和 AI 生成图片都保存附件与账号、会话的关联记录。
- 通过统一附件存储 Service 隔离业务逻辑和存储实现；本期只实现 `ATTACHMENT_STORAGE_ROOT` 持久化目录，不实现多后端并行、自动切换或失败降级，未来可替换为对象存储实现。
- 返回附件 ID、展示名称和受控访问地址，不暴露任意本地路径。
- 附件与会话保持相同留存周期，本期不自动过期；退出、角色调整和账号状态调整不删除附件。

#### CHAT-07 图片读取

- 只通过 `/chat/attachments/{attachmentId}` 受控接口读取附件，并校验当前账号和会话归属。
- 账号 A 的附件不能被账号 B 通过猜测文件名或 URL 访问。
- 本期不提供会话删除；未来增加删除能力时，删除会话必须同时可靠删除附件元数据和实际文件。

### 8.4 会话接口

| 方法 | 接口 | 权限 | 说明 |
| --- | --- | --- | --- |
| `POST` | `/chat/sessions` | 已登录 | 创建当前账号会话 |
| `GET` | `/chat/sessions` | 已登录 | 按标题搜索和游标分页查询当前账号会话列表 |
| `GET` | `/chat/sessions/{sessionId}/messages` | 会话所有者 | 查询会话消息 |
| `POST` | `/chat/sessions/{sessionId}/attachments` | 会话所有者 | 上传会话图片 |
| `GET` | `/chat/attachments/{attachmentId}` | 附件所有者 | 读取会话图片 |

现有 `/ai/**` 对话接口可以继续保留，但必须统一接入登录校验和会话所有权校验，不能仅凭请求中的 `chatId` 读取或写入数据。

### 8.5 阶段完成标准

- 访客不能调用 Chat、Manus 和上传图片接口。
- 普通用户不能调用账号管理接口。
- 账号 A 无法读取、继续或上传到账号 B 的会话。
- 修改请求中的会话 ID 不会返回其他账号数据。
- 同一账号重新登录或更换设备后，可以读取相同会话和消息。
- 空白草稿不写入服务端，首次有效发送后按规则生成固定标题。
- 会话搜索不跨账号、不查询消息正文，游标分页在相同更新时间下不重复、不遗漏。
- Manus 运行或待答状态在服务重启后转为已中断，不自动重跑，历史信息仍可查看。
- 仅合规图片可写入持久化目录，上传与 AI 生成图片均通过受控接口按账号读取。
- 账号退出后，认证失效且不能继续调用受限接口。
- admin 的 Chat 记录与普通用户一样仅归属于自身。

## 九、阶段三：登录注册及账号状态前端（P1）

#### UI-AUTH-07 登录注册切换

- 普通用户直接访问时返回 Landing 并提示“当前账号无 Console 访问权限”。

### 9.6 Chat 账号会话页面

#### UI-CHAT-01 服务端会话列表

- 支持按标题搜索当前账号会话，搜索由服务端执行，不在前端过滤消息正文。
- 每批加载 20 条并提供“加载更多”，使用服务端游标读取下一批；搜索或账号变化时重置游标和列表。
- 当前会话展示标题、更新时间和应用类型。

#### UI-CHAT-02 会话内容恢复

- 切换会话时从服务端加载消息。
- 加载新账号数据前清空旧账号消息，禁止短暂显示上一账号内容。
- 输入区提示当前会话会保存到账号中。
- 保留 Love App、Manus、图片上传、Todo 和补充提问等现有能力。

### 9.7 SSE 认证适配

- Axios 请求统一开启 Cookie 凭据。
- EventSource 创建时启用凭据，并处理未认证和无权限场景。
- Fetch SSE 请求携带 Cookie 凭据。
- 建立流式请求前或后续请求收到未认证时，清理敏感页面状态并引导重新登录。
- 已建立的 SSE 或 Manus 请求执行期间会话到期时，不主动中断该次请求；请求结束后的下一次请求重新登录。

### 9.8 阶段完成标准

- 登录和注册弹窗与原型的结构、字段和主要交互一致。
- 登录、注册、退出后页头状态立即正确变化。
- 访客访问 Chat 时先登录，关闭弹窗后不进入 Chat。
- 普通用户看不到 Console 入口，直接访问也无法停留在 Console。
- 切换账号时不会显示上一账号会话和消息。
- 刷新页面后登录状态、会话列表和历史消息可以恢复。

## 十、阶段四：Console 账号管理（P1）

### 10.1 账号列表

#### ADMIN-01 列表查询

- 在 Console 首屏最前方新增账号管理区域，保留原有系统状态、会话管理、调试面板和请求日志。
- 展示账号、角色、状态、注册时间、最后登录时间和操作。
- 当前登录 admin 行展示“当前账号”。
- 从未登录账号的最后登录时间展示“从未登录”。
- 列表响应不包含密码、密码摘要和认证信息。

#### ADMIN-02 搜索、筛选与分页

- 支持账号关键词搜索。
- 支持全部、普通用户、admin 角色筛选。
- 支持全部、正常、已停用状态筛选。
- 搜索、角色和状态可以组合使用。
- 账号关键词先去除首尾空格，英文字母不区分大小写。
- 无结果时展示“暂无符合条件的账号”。
- 默认每页 20 条，使用从第 1 页开始的页码分页，响应返回总记录数和总页数。
- 搜索、角色或状态变化时重置到第 1 页；后端限制每页数量最小为 1、最大为 100。
- 本期前端不提供每页数量选择。

### 10.2 角色管理

#### ADMIN-03 调整角色

- admin 可以调整其他账号的角色。
- 操作前二次确认，明确目标账号和新角色。
- 当前登录 admin 不能修改自己的角色。
- 修改成功后列表立即刷新，目标账号的 Console 权限立即生效或失效。
- 角色修改与“保留至少一个正常 admin”校验在同一事务中完成。

### 10.3 状态管理

#### ADMIN-04 停用账号

- admin 可以停用其他正常账号。
- 操作前二次确认，并提示“该账号退出后将无法再次登录”。
- 当前登录 admin 不能停用自己。
- 停用不能导致系统不存在正常状态的 admin。
- 停用不主动中断目标账号当前认证会话；目标账号退出后不能再次登录。

#### ADMIN-05 启用账号

- admin 可以重新启用已停用账号。
- 启用成功后账号可以再次登录。
- 账号角色、会话、消息和附件保持不变。

### 10.4 管理接口

| 方法 | 接口 | 权限 | 说明 |
| --- | --- | --- | --- |
| `GET` | `/admin/accounts` | admin | 搜索、筛选和分页查询账号 |
| `PATCH` | `/admin/accounts/{accountId}/role` | admin | 调整目标账号角色 |
| `PATCH` | `/admin/accounts/{accountId}/status` | admin | 启用或停用目标账号 |

### 10.5 并发和安全约束

- “至少保留一个正常 admin”必须在数据库事务中重新统计并锁定相关账号，不能只依赖页面按钮禁用。
- 同一账号的并发角色或状态修改需要检测更新冲突，避免后提交覆盖先提交结果。
- 当前账号限制由后端根据认证账号 ID 判断，不能依赖前端传入“当前账号”标志。
- 所有管理操作记录操作者、目标账号、操作前后值、时间和结果，不记录密码信息。

### 10.6 阶段完成标准

- 普通用户不能访问任何账号管理接口。
- admin 可以组合搜索、筛选和分页查询账号。
- 账号列表按每页 20 条返回，搜索或筛选变化时回到第 1 页，并正确展示总记录数和总页数。
- admin 可以调整其他账号角色并立即影响权限。
- admin 可以停用和启用其他账号。
- 当前 admin 不能调整自己的角色或停用自己。
- 并发操作也不能导致系统不存在正常状态的 admin。
- Console 不提供账号新建、删除、密码查看和聊天内容查看入口。
- 原有 Console 功能继续可用。

## 十一、统一错误与提示

后端需要补充认证和权限相关业务错误，并由全局异常处理统一响应：

| 场景 | 建议响应语义 | 前端提示 |
| --- | --- | --- |
| 未登录访问受限接口 | 未认证 | 请先登录后访问 |
| 已登录但角色不足 | 无权限 | 当前账号无 Console 访问权限 |
| 账号或密码错误 | 登录失败 | 账号或密码错误 |
| 账号已停用 | 登录失败 | 账号已停用，请联系管理员 |
| 注册账号重复 | 资源冲突 | 该账号已存在，请更换账号 |
| 注册账号格式不符合规则 | 参数错误 | 账号需为 3～32 个字符，仅支持中文、英文字母、数字、下划线、短横线和英文句点，且首尾不能为符号 |
| 密码规则不满足 | 参数错误 | 密码至少 6 位，且必须同时包含英文字母和数字 |
| 会话不属于当前账号 | 禁止访问或资源不存在 | 无权访问该会话 |
| 修改当前 admin 自身 | 业务规则冲突 | 不能调整当前账号 |
| 最后一个正常 admin | 业务规则冲突 | 系统必须保留至少一个正常状态的 admin |

认证和权限错误的 HTTP 状态、业务错误码及提示文案需要保持稳定，Axios、EventSource 和 Fetch SSE 使用同一套前端处理逻辑。

## 十二、关键业务流程

### 12.1 注册并进入 Chat

1. 访客点击 Chat。
2. 路由记录 Chat 为目标页面并打开登录弹窗。
3. 用户切换到注册，提交账号、密码和确认密码。
4. 后端校验参数、加密密码、创建普通账号并建立认证会话。
5. 前端加载当前账号信息并清空访客期间的临时会话状态。
6. 前端进入 Chat，查询当前账号会话列表；点击新建时只创建本地空白草稿。
7. 用户首次发送有效消息时，前端先请求服务端创建正式会话，再使用服务端会话 ID 发送消息。

### 12.2 登录并恢复历史会话

1. 用户提交账号和密码。
2. 后端统一校验账号、密码和账号状态。
3. 登录成功后建立认证会话并更新最后登录时间。
4. 前端查询当前账号的会话列表。
5. 用户选择会话后，后端通过当前账号和会话 ID 联合校验并返回消息。

### 12.3 账号切换

1. 账号 A 退出登录。
2. 前端停止 SSE、清空会话列表、消息、附件、Todo 和待答问题，然后返回 Landing。
3. 账号 B 登录。
4. 前端仅加载账号 B 的会话列表和消息。
5. 后端即使收到账号 A 的会话 ID，也因所有权不匹配而拒绝访问。

### 12.4 admin 调整角色

1. admin 在 Console 选择目标账号并发起角色调整。
2. 前端展示目标账号和调整后角色，要求二次确认。
3. 后端校验操作者是 admin、目标不是自己，并验证至少保留一个正常 admin。
4. 后端在事务中更新角色并记录管理日志。
5. 目标账号后续访问 Console 时，服务端按最新角色立即拒绝或允许。

### 12.5 admin 停用账号

1. admin 对其他正常账号发起停用并二次确认。
2. 后端校验不能停用自己，也不能停用最后一个正常 admin。
3. 后端更新账号状态，但不主动清除目标账号已有认证会话。
4. 目标账号退出后再次登录时，后端返回账号已停用提示。
5. 重新启用后，该账号恢复登录能力，原会话数据不变。

## 十三、实施改造范围

### 13.1 后端

- 新增账号、认证、安全、会话元数据和附件归属相关领域代码。
- 接入 Spring Security，统一认证会话、权限规则和安全 Cookie。
- 扩展业务错误码和全局异常处理。
- 改造全部 AI、Manus、Todo 和图片接口，统一验证会话所有权。
- 持久化 Manus 执行状态，并在服务启动时将未完成执行更新为已中断。
- 通过 `ATTACHMENT_STORAGE_ROOT` 管理统一附件存储，并对上传类型、大小和真实内容执行校验。
- 改造 MySQL ChatMemory，使会话存取具备账号归属前置校验。
- 增加账号管理查询和修改接口。
- 关键登录、注册、鉴权失败、会话越权和管理操作打印结构化日志，禁止输出敏感信息。

### 13.2 前端

- 新增认证 Store、登录注册弹窗和统一提示能力。
- 改造全局页头和路由守卫。
- Axios、EventSource 和 Fetch SSE 统一携带认证信息并处理登录失效。
- 认证 Store 统一管理 CSRF Token 生命周期，在登录、注册成功后立即刷新 Token，CSRF `403` 时重新确认 Token 与登录态。
- Chat 会话列表、消息和附件改为服务端数据源。
- Console 首屏增加账号管理区域，保留原有功能。
- 页面关键状态切换处清理上一账号数据，禁止账号间页面状态泄露。

### 13.3 配置

- 配置服务端认证会话 24 小时不活跃期限、7 天绝对有效期和 Cookie 安全属性。
- 初始 admin 只通过 `BOOTSTRAP_ADMIN_ENABLED`、`BOOTSTRAP_ADMIN_ACCOUNT`、`BOOTSTRAP_ADMIN_PASSWORD` 环境变量配置。
- 附件持久化根目录只通过 `ATTACHMENT_STORAGE_ROOT` 环境变量配置。
- 正式环境固定启用 MySQL 会话持久化。
- 初始 admin 密码、数据库密码和会话密钥不得写入代码仓库或日志。

## 十四、验收顺序

### 14.1 第一轮：账号基础

- 注册合法账号并自动登录。
- 验证账号首尾空格、大小写不敏感唯一性、3～32 字符范围、允许字符、密码规则、确认密码和停用账号提示。
- 验证密码不在数据库明文字段、接口响应或日志中出现。
- 验证刷新和关闭浏览器后恢复登录状态、24 小时不活跃与 7 天绝对期限、多设备并发登录以及退出只注销当前设备。
- 验证登录或注册后旧 CSRF Token 被拒绝，重新获取的新 Token 可以完成退出及其他修改请求。
- 验证角色变更即时生效、停用不强制注销已有会话，以及流式请求执行中会话到期不被主动中断。
- 验证账号表为空时按环境变量幂等创建初始 admin，账号表非空时不创建、不提权、不覆盖密码。

### 14.2 第二轮：权限和数据隔离

- 分别使用账号 A、账号 B 和 admin 验证页面与接口权限。
- 使用账号 B 构造账号 A 的会话、消息和附件 ID，确认后端拒绝访问。
- 验证账号切换过程不展示上一账号数据。
- 验证同一账号重新登录和更换设备后可以恢复历史会话。
- 验证首次有效发送创建会话、标题生成规则、服务端标题搜索和每批 20 条的稳定游标分页。
- 验证 Manus 未完成执行在服务重启后转为已中断，不自动重跑，历史消息、Todo 和只读问题可查看。
- 验证 JPEG、PNG、WebP、真实内容校验、附件受控访问和长期留存；图片大小至少覆盖 1 MB 以下、1～10 MB、超过 10 MB 三档，确认合法大图能够进入业务链路，超限请求稳定返回 HTTP 413 和业务码 41301。

### 14.3 第三轮：前端原型和交互

- 对照 4 张原型图检查页头、弹窗、Chat 会话和 Console 账号管理布局。
- 验证登录注册切换、原目标页面跳转、退出返回 Landing 和错误提示。
- 验证同步、SSE、SseEmitter、Manus、Todo 和图片能力在认证后仍正常工作。

### 14.4 第四轮：账号管理

- 验证账号搜索、角色筛选、状态筛选和分页组合。
- 验证账号列表每页 20 条、总记录数、总页数和筛选变化后重置到第 1 页。
- 验证角色调整立即影响 Console 权限。
- 验证停用账号退出前可继续使用、退出后不能登录。
- 验证 admin 不能修改或停用自己。
- 验证任何操作都不能移除最后一个正常 admin。

## 十五、已确认需求基线

此前 8 项规则已全部确认，实施与验收统一使用以下基线：

| 编号 | 主题 | 已确认规则 |
| --- | --- | --- |
| 1 | 账号规范化 | 去除首尾空格；英文字母大小写不敏感；保留清理后的原始大小写用于展示 |
| 2 | 账号范围 | 3～32 个字符；允许中文、英文字母、数字、下划线、短横线和英文句点；首尾不能为符号 |
| 3 | 登录会话 | 浏览器关闭后保持登录；24 小时不活跃失效；最长 7 天；允许多设备；退出只影响当前设备；角色即时生效；停用不强制中断已有会话；流式请求执行中不强制中断 |
| 4 | 初始 admin | 仅通过环境变量读取配置；仅账号表为空时幂等创建；既有数据不自动创建、提权或覆盖密码；密码至少 12 位并包含字母、数字和特殊字符 |
| 5 | 会话标题与搜索 | 首次有效发送创建会话；标题取首条文本并清理空白，总长度最多 30 个字符，超出时第 30 个字符为省略号；纯图片为“图片会话”；标题不自动变化；仅服务端搜索当前账号标题 |
| 6 | 分页 | 会话每批 20 条游标分页；账号列表每页 20 条页码分页；后端数量范围 1～100；本期不提供数量选择 |
| 7 | Manus 重启 | 持久化执行记录；重启后未完成执行转为 `INTERRUPTED`；不自动续跑；保留历史消息、Todo 和只读问题；重新发起使用新执行 ID |
| 8 | 图片 | `ATTACHMENT_STORAGE_ROOT` 指定持久化目录；UUID 文件名；JPEG、PNG、WebP；单张不超过 10 MB；三重类型校验；受控接口访问；随会话长期保留 |

上述规则与 `01-登录与注册.md` V1.2、`02-访问权限与账号管理.md` V1.1 共同构成本期正式需求基线，后续设计、编码和验收统一以本基线为准。
